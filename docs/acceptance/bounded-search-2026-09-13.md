# 受控多路线搜索接通记录

日期：2026-09-13。状态：四项首版已施工，本地联合验收完成，原始失败与修复后复验记录均保留。本轮没有发起新的付费模型请求，不构成解题能力提升结论。

## 本轮范围

本轮接通蓝图升级的四项运行基础：定点修复、工具辅助检查、多路线搜索和题内结构化记忆。`solver_controller=bounded_search_v1` 是可选控制器；`legacy` 仍是默认。控制器管理版本、路线工作、阶段和预算，不替模型判断自然语言证明是否正确。

## 如何开启

工作台中从“启动研究”进入运行设置，在“求解控制器”选择“受控多路线搜索”。该选择会强制自主运行，并在启动时冻结搜索配置；高级设置提供四个开关：启用定点修复、启用工具检查、启用题内记忆、启用多路线。既有任务可在“任务额度与研究设置”查看已冻结的控制器和路线配置，不能事后改写为另一种控制器。

CLI 对应为 `--solver-controller bounded_search_v1`，并可用 `--search-config PATH` 读取 JSON 配置。受控模式要求累计输出上限；默认示例为 12 次请求、32,768 输出 token、最多 3 条路线、最多同时 2 条路线、每路线最多 3 步、最多 1 次修复，另预留检查与最终提交额度。实际值以冻结的 `SearchConfig` 和项目/任务预算为准。

## 已接通的行为

- 会话保存原题 revision、控制器版本、配置哈希、阶段、决策序号和预算池。
- 分析阶段最多保存三条路线，并以 `core_reduction/key_lemmas/assumptions` 的精确 JSON 哈希去重；相同记录不重复扩展。模型可显式标记疑似同核心路线并说明理由，在假设相同且引用较早路线时降低优先级，保留路线而不认证数学等价。
- 预算分为探索、检查/修复、收尾三个池；请求数、输出预留、在途工作和未知请求都进入共享账本。控制器不以字数或模型自报信心认定“进展”。
- 缺口、路线进度、候选 revision、记忆条目和工具回执带版本与适用条件。题内记忆按根会话和路线隔离，分页返回 revision 引用；跨路线共享需要显式导入并保留假设。
- 检查结果只在实际材料完整且范围满足时影响路线状态；模型提出的缺口或检查映射仍是模型证据，不是形式化证明。

## 实现与设计的差异

会话阶段使用 `analysis/search/final/terminated`；核查和修复是搜索阶段中的 `check/repair` 工作，共用受保护的 `check` 额度池。排序按候选待审查、具体缺口待修复、可推进路线分级，再按首轮机会、人工优先级和创建序号选择。首版使用可回放的确定性规则，不采用学习得到的评分器，也不要求用满额度。

精确哈希不能识别措辞不同但数学等价的路线；疑似语义重复、路线候选、缺口分类和修复内容仍由模型提出。服务端校验 schema、版本、权限、范围和预算，缺口同时保存目标正文哈希，避免把旧锚点无条件套在新版本上。工具检查回执只代表实际执行范围，不能自动升级成一般定理；程序失败不成为数学反例。

最终选择先排除仍有未处理反例的候选，再比较审查、目标覆盖、缺口和固定序号。没有可交付候选时允许明确弃答；答案提交与证明完成分别报告。工作台中的路线人工操作会计入评测审计，不能进入无人对照。

路线的 `assumptions` 明确指超出原题的未证附加条件，不能靠后续空数组报告抹除；路线产物和共享记忆继承这些条件。首版采取保守策略：要证明无附加条件的原题，应使用无附加条件的路线，不自动认证自然语言中的“已经解除假设”。

## 能力结论的边界

- 未进行新的 DeepSeek/DSH 付费比较；独立多采样基线用于消融，不能称为 DSH。现有 `self_refine` 名称保持为固定自查基线。
- 仍需在冻结留出题上验证候选覆盖、最终选择、缺口修复、成本和延迟；内部路线/记忆计数不是正确率。
- 形式化证明、联网文献检索、美元硬上限和跨题学习仍未纳入本轮实现。
