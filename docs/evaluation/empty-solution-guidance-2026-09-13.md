# 空解集候选与未解决状态

本轮加入与具体题目无关的解集指导，提示版本更新为 `research-operations-v9`。没有写入数论评测题的标准答案，也没有发起新的付费模型请求。

## 行为约定

- 对存在性或求全部解的问题，不预设解存在；路线可以构造解、分类全部解，或从必要条件推出不存在解。路线由数学证据决定，不强制每题优先证明无解。
- 完整的无解证明可以提交为候选，答案使用 $\boxed{\varnothing}$，随后进入与非空解集相同的独立审查和完成检查。
- 无解论证必须覆盖原题全部定义域和例外情形。有限枚举需要已证明的界才能成为穷尽检查；搜索失败、超时、预算耗尽均不能证明无解。
- 尚未解出时保留缺口并报告进展或停滞，不使用空集作为占位答案。候选引用字段为空表示引用本次正文，与数学空集无关。
- 审查关注量词、覆盖范围、必要条件与充分条件、例外及定理前提。一个符合原题条件的解即可推翻空解集主张。

共享指导同时用于 Agent 研究/审查提示和 direct、自查及独立采样基线的初始指导，避免比较时只给 Agent 提示。历史运行记录保持原样。

## 验证与局限

提示和协议测试检查共享指导、空集提取与未解决状态的区别；控制器集成测试覆盖完整空解集候选、有限搜索存在覆盖缺口、停滞无候选以及非空解集对照。测试使用本地合成提供器，不调用 DeepSeek。

集成测试的审查结论由测试提供器给出，因此验证的是审查结果能否正确控制完成流程，不能证明真实模型必然识别错误证明。这次修改改善提示与工作流语义；是否提升数学解题率仍需冻结配置后的实测。此前运行暴露的预算池分配和导出问题不属于本轮修复。
