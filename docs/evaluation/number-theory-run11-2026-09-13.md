# 自适应预算修复与数论 run11

用户授权按提出的预算调度设计修改，并使用剩余额度闭卷重跑数论题。

## 实现

新建受控运行默认 `budget_policy=adaptive`；已存储且未包含该字段的会话按旧 fixed 策略解释，也可显式选择 fixed 复现旧机制。提示版本 `research-operations-v11`。

自适应模式使用一份根运行总账，所有非 released 请求均占额度。spent 使用实际输出用量；unknown、在途及缺失用量保留预留占用。尚无请求的排队工作计入占用，不能把同一余量重复分配。各阶段共享余额，界面只显示一份总预算。

探索可使用旧检查池超出最低审查保障的部分。探索及证明修复保留最低独立审查和收尾的 token、请求数；检查保留收尾，最终交付可用其余余额。恢复也经过同一准入，不能绕过保障或忽略前次失败消耗。

规划限额生成路线卡，关闭长推理并使用兼容的 provider_default effort；证明和审查仍用 High。自适应只推进一条活跃路线，优先延续已有进展，停滞后再切换。预算不足以支持有意义的工作时明确记录 budget_stop；无法启动规划的运行直接终止。

工作进程每次派发前读取新容量并保持供应商上限与账本预留一致。长度恢复只处理更小的子目标，且可用上限不得低于该次失败请求的上限；不足则记录 search_recovery_capacity，不再付费派发更小的重试。格式恢复保留上一轮的具体字段反馈机制。

## 离线验证

模拟测试覆盖全局 unknown 和排队占用、同一工作恢复仍计入历史消耗、token/请求数的交付预留、规划容量不足即终止、单路线连续推进后独立审查及最终完成、缩水恢复拒发、足额恢复、供应商参数与预留一致。已有固定分池与双路线测试显式选 fixed；暂停/在途测试使用新策略合法请求上限。测试提供器不访问外网，不证明模型数学判断正确。

## 本轮冻结配置

仅原题 `imo-bench-number_theory-081`，不传入历史答案、推导或标准答案。DeepSeek v4-flash；研究模式、reviewed_answer；最多 8 次请求、累计 98,305 输出 token，单次最多 32,768。规划上限 8,192；推进最低 16,384；最低审查预留 16,384、收尾预留 8,192。检查配置期望额度 32,768，可在总账内动态调配。三条候选路线、一条活跃，最多六次推进和两次证明修复。单题 3,600 秒、单请求 600 秒，长度恢复 high，未知请求保留占用且预算内至多续试一次。

配置位于 `data/evaluation/number-theory-run11-search-config.json`。启用固定离线 Docker 沙箱和精确计算器，无联网检索工具、无人干预；评分在求解结束后单独执行。本轮主要验证流程，不作为与裸模型或 DSH 的公平能力比较。此前含假设文本的导出缺陷没有在本轮修复。
