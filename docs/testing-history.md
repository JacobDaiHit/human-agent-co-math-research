保留当前可执行的回归测试、原始题面、独立答案键、设计说明，以及最新一轮真实测试的完整记录。退役协议测试副本和旧验收文字已合并删除，共 77 个文本文件。旧试跑数据库、长输出与截图已提取摘要，但批量删除被当前环境保护拒绝，原文件仍保留，不绕过限制。旧版受控路线流程只支持历史读取，不再派发请求；用户的工作台研究数据库、密钥、其他项目和数学题库不在清理范围内。

已删除的历史文本可从 Git 找回；仍保留的 20 个旧试跑目录约 81 MiB，另有旧截图。如随后人工清理，忽略目录内的试跑输出不能仅凭 Git 恢复。旧费用未知项仍在下文保留，清理文件不代表退还额度或完成对账。

## 过去遇到的问题

1. 长证明被放进整份严格格式的数据包。引号、括号、研究与审查角色字段等小错误会让数学正文整份被拒收，随后又花钱修格式。现在只给可执行工具规定参数，数学推导按普通正文保存。
2. 研究、计算、读取和收尾分别消耗固定推进轮次；初始路线、推进次数和分阶段额度阻止后续探索。有些试验仍有总余量，却因探索池耗尽停止。现在同一个研究任务可以连续使用工具，局部目标、方法和合作安排由模型决定，所有成员使用一份总账。
3. 长推理达到输出上限时，已有思考没有成为下一轮可见的研究材料；缩成几千词元的起步阶段也仍会截断。现在保留已付费推导并接续研究，不自动降低思考强度，不丢弃正文重做起步。
4. 必经审查、关键词和方框答案数量被用于判断研究是否完成。重复展示相同答案也曾阻断交付。这些规则不能理解一般数学证明，已退出自主求解；模型可以按需寻找反例、检查关键推导，但不需要审批或投票。
5. 历史记录和来源编号不等于可接续的工作稿。现在每人维护个人工作稿，主研究者整理公共工作稿；完整材料保存、按需找回。同一道原题的新研究可接续已有笔记，换题或改题不会自动混用。
6. 讨论容易被主研究者的候选结论引导，但强制所有新同伴先重做整题也会浪费研究。现在由研究者明确选择独立探索或针对性合作：前者可以研究中性局部问题并隔离其他成员结论，后者立即接收相关推导。不同意见不阻止交付；已交流成员不因重开对话恢复独立性，程序不认证问题是否中性，也不保证模型从此不会附和。
7. 多人同时请求时，暂时被在途预留占满的额度曾被当作整题已耗尽。现在等待用量结算、释放执行槽，再按实际余量继续；预留与实际传给提供方的输出上限一致。
8. 导出曾把自然语言假设当作版本编号；报告曾把程序完成、缺答、数学错误混为一谈。现行报告区分运行状态、研究者声明、完整提交和可选短答案；只有证明也能交付。“未解决进展已提交”不等于解出了题，程序正常结束也不等于数学正确。
9. 实测缓存命中很低。离线排查发现，开场中的资源余额和成员名单变化会重写已有输入；换局部任务也曾重建开场。现在保存对话开场、系统说明和工具目录，目标、成员、额度和消息变化依次追加，工具回执保留当时读取的材料；同一成员换任务、等待或暂停恢复通常继续原对话。真实命中率仍以提供方报告为准，不从本地稳定性测试推算保证值。
10. 多槽执行器曾可能因短暂无任务提前退出，也在本轮并发检查中暴露“研究已完成但空闲槽不能共同退出”的问题。现在保留待工作槽，接到新任务时撤销空闲状态，全部确实空闲后退出；同伴结束或失败通知所有等待它的成员，等待释放执行槽。等待中的成员改派新目标时撤销旧等待，接续原对话，并直接接收指定任务材料，不让新目标堵在旧等待任务后面。
