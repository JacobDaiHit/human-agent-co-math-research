日期：2026-09-13。状态：四项首版已施工并完成本地联合验收，未启动新付费评测。实现与复验记录见 [受控搜索验收](../docs/acceptance/bounded-search-2026-09-13.md)。

范围已确认：定点修复、工具辅助检查、多路线搜索、题内结构化记忆四项全部纳入完整升级。分阶段仅表示工程依赖顺序，不表示第三、四项可留待以后决定。具体数据结构、调度、预算、恢复和验收见 [四项一体化施工设计](四项一体化求解升级_施工设计_v0.3_2026-09-13.md)。原稿先交付设计；用户随后授权施工，本轮已实现运行代码。

本文是蓝图 v0.2 的增量升级：保留开放研究工作台，新增可独立运行、可消融的求解控制器。目标是在固定底模和可比较成本下，提高最终答案正确率与完整证明成功率。两项指标分别报告，不能互相代替。

本状态更新只说明运行链路已接入，不表示四项已经在新题上带来能力提升；最终测试计数、真实模型结果和外部盲评分仍由验收记录补填。

DSH 按用户定义指 DeepSeek harness。此前把它解释成 DeepSeek 自查不准确。当前仓库的 `self_refine` 只是一个自查基线，不能直接命名为 DSH；正式对照前必须确定 DSH 的仓库、提交版本、提示词、工具、重试和预算策略。本文不假定某个尚未指定的 harness 有或没有搜索能力。

## 1. 调研应如何转化为设计依据

| 证据 | 可借鉴的机制 | 不应据此承诺的事情 |
| --- | --- | --- |
| [Self-Consistency](https://arxiv.org/abs/2203.11171) | 独立采样与答案聚合值得作为强基线 | 较早模型、较易任务上的增益不等于当前 DS 在 IMO 难题上的增益；多采样要计成本 |
| [Math-Shepherd](https://arxiv.org/abs/2312.08935) | 过程定位与候选排序，比只给通过/失败更有用 | 论文包含过程模型训练和策略优化；提示词审查者不等于训练好的 PRM |
| [rStar-Math](https://arxiv.org/abs/2501.04519) | 搜索、代码反馈、过程评价协同 | 其结果还依赖大规模合成数据及迭代训练，不是纯 wrapper 收益 |
| [DeepSeek-Prover-V1.5](https://github.com/deepseek-ai/DeepSeek-Prover-V1.5) | 保存部分进展、借助验证反馈扩展路线 | Lean 验证信号不能用自然语言审查分数直接替代；搜索比较也不能忽略额外计算 |
| [RMA](https://arxiv.org/abs/2605.22875) | 结构化题内记忆与反复修订适合长程任务 | 作者报告十题研究评测中的八题解决，不足以证明本项目同成本优于 DSH |

以上为针对核心设计依据的原始来源核对，不是对附件所有数字与消融表的独立复现。ToRA 等涉及工具适配训练的工作，也不宜归入纯编排提升。本文不把附件中“搜索、验证、工具、记忆的乘积”当作数学定律，不把未经复核的细分胜率写成验收指标。

**本轮设计约束：不训练或更换底模；不接形式化证明；闭卷求解不提供网页和文献检索。** 本次为蓝图查阅论文，不意味着 benchmark 求解进程获得联网工具。远程 DS 推理接口是必要通信，除此之外沙箱断网、资料按冻结清单供给。

## 3. 求解流程：保留自由草稿，结构化关键决策

一次求解围绕以下循环展开：分析原题，提出少量不同路线，完成一个有意义的局部目标，检查关键推导，修复或换路，再组装最终答案。

不为每行等式创建节点，不要求每次想法都单独请求审查。Worker 可以在一次响应中给出完整局部论证。只有跨任务复用、改变路线或支撑最终结论的内容，才进入结构化状态。

### 3.1 题目分析与路线设计

分析结果包含原题版本、变量与定义域、量词、目标类型、允许假设、边界情况和子目标。不允许分析器悄悄把原题改成更弱问题。

首轮最多提出三条路线，默认激活两条；极小预算只保留一条。路线卡写清核心归约、需要的关键引理、最便宜的检验和可能障碍。反证、构造、计算实验等是可选方向，不能机械地给每题安排相同角色。

判断多样性以核心归约、依赖引理和构造差异为依据。文字不同或换一个角色名不算新路线；语义去重不确定时保留并标记，不能自动宣称数学等价。首轮候选独立形成后再共享成果，减少互相模仿。

### 3.2 Worker 的任务合同

每次只要求完成一个明确目标，例如证明一个引理、攻击一条不等式、补一个存在性步骤，或检查一组边界。

输入包括目标、适用假设、引用的固定版本、必须处理的缺口、禁用的已否定推导，以及剩余额度。输出包括实际进展、可检查的论证、工具证据、残留问题和下一步建议。模型不负责修改自己的预算或签发最终证明证书。

任务拆分按数学粒度进行。把整道题切成许多很小请求会增加输入和协议成本，必须在消融中检验其价值。

### 3.3 过程审查与定点修复

审查意见新增：目标版本、已读范围、问题所在步骤、涉及前提、缺陷类型、反例或检查证据、仍未发现问题的部分、建议修复目标。

审查者报告“所检查范围内最早定位的缺口”，不能保证自动找到了全篇第一个错误。“此前未发现错误”也不是此前步骤已获证明。

控制器按缺陷分流：

- 局部计算错误：工具复核，替换该步，并重查受影响后续。
- 漏条件或量词错误：明确缺失条件；不能擅自强化原题假设。
- 关键引理被反例否定：撤下依赖该引理的证明方案，保留不依赖它的其他进展。
- 尚未补足的逻辑步骤：生成定点修复任务；一次无实质进展后优先换路。
- 审查意见互相冲突：保持争议状态，对争议点作针对性检查，不以票数判真。

同一版本、同一缺口默认最多一次修补；再次尝试须有新证据、新归约或明确的新方案。该上限是开发集可调整的控制策略，不是数学上判定路线不可行。

例如旧失败中的候选关系

\[
s_2(M-a)\leq s_2(M)+s_2(a)
\]

可被满足条件的精确算例否定：

\[
M=8,\quad a=1,\quad s_2(7)=3>2=s_2(8)+s_2(1).
\]

正确动作是禁用这一步及其依赖方案，要求替代引理或换路，而不是重写整篇同类证明。这个算例只能否定候选关系，不能否定原题的答案。它仅进入开发回归，不注入未来闭卷测试题上下文。

### 3.4 工具反馈与证据分级

先复用现有精确计算与隔离沙箱；需要符号计算库时另做固定版本、固定镜像验收。不把 Python 能运行当作 SymPy 已接入，也不把符号化简成功当作一般定理已证明。

证据分为：模型提出、自然语言审查未发现问题、有限范围实验、满足条件的精确反例、指定范围的精确计算。保留以后接入形式化证书的类型，但本轮不产生它。

任何实验必须保存输入、代码、镜像、输出和被检查的命题版本。代码本身可能错，特别是定义域、浮点精度和题意翻译；关键反例需要核对它确实满足命题前提。有限枚举无反例不能推出无限范围成立。自然语言 Writer 可以使用已审查结果，但必须保留其证据等级和未解除假设。

### 3.5 题内记忆与依赖失效

新增四类轻量状态，依托已有对象和版本机制，不再建一套平行事实数据库：

| 状态 | 关键内容 |
| --- | --- |
| 路线 | 目标、核心方法、依赖、检查点、花费、暂停原因 |
| 缺口 | 目标版本、问题步骤、证据、影响范围、修复尝试 |
| 证据 | 类型、适用范围、来源、工具或审查回执 |
| 决策 | 扩展/检查/修复/暂停/收尾的原因与预算快照 |

失败记忆记录“这次推导为什么失败”，不要总结成整个数学方法不可行。Worker 只接收目标相关的依赖闭包、局部失败及当前缺口；需要原文时可按版本取回。摘要是索引，不能取代关键证明全文。

只有某个被采用的证明方案失效时才传播影响；有独立替代证明的结论不自动变成错误。主评测逐题、逐条件、逐重复隔离记忆。跨题学习作为单独实验，知识库冻结并给双方等同访问。

## 4. 搜索调度与预算

### 4.1 第一版采用有宽度上限的最佳优先调度

候选动作是继续推导、检查、修复、换路、汇总或停止。调度器用可审计规则决定动作，模型只提出建议。

优先顺序：先处理能影响最终结论的具体反证；再修补接近形成完整候选的局部缺口；其次扩展有新增实质成果的路线；最后探索新路线。每个开发阶段预留少量探索机会，避免某个初期高评价路线独占额度。

“进展”指形成可检查引理、关闭一个明确子目标或排除具体错误，不能按字数、节点数或自报信心评分。对未校准的 LLM 分数不解释成成功概率。路线排序允许出错，保留次优候选和恢复点。

先用规则调度并与轮转、独立多采样比较。只有证据显示分支选择稳定有益，才考虑 MCTS；自然语言状态、验证噪声和每次扩展成本都使直接照搬形式证明搜索不可靠。

### 4.2 从提示预留升级为硬性保护

当前预留提示只是 planning-only。新增探索、审查/修复、最终提交三个额度池，覆盖根任务、子任务和协议恢复。最终提交额度只能由收尾动作消费；控制器在探索额度用尽前自动进入收尾阶段。

额度按开发时冻结的配置分配，不把固定比例当作普适最优策略。施工设计给出八请求实例，同时保护输出、请求槽位和墙钟时间；只有 token 余额但没有请求次数同样无法收尾。

预算同时满足：

\[
B_{\mathrm{explore}}+B_{\mathrm{check\text{/}repair}}+B_{\mathrm{final}}\leq B_{\mathrm{total}}.
\]

初期保留现有输出硬上限与请求上限；输入、缓存、工具运行时间和费用单独记账。后续成本上限需要计价版本、保守输入估算和结算机制，不能把输出上限改名为美元硬上限。

格式恢复、输出截断、工具程序失败、数学推导失败分别记录。未知请求继续占用，在原预算内最多续试一次。预留可以保证存在收尾机会，不能保证网络返回或模型一定生成有效最终答案。

### 4.3 最终答案与完整证明分开

预算将尽时，答案模式必须进入统一最终提交步骤：提交当前选定候选并如实标注证明缺口，或明确弃答。不得让评分器从历史中替系统挑答案。

研究模式继续要求检查引用闭包和证明衔接；未解决的缺口不能包装为完成。固定版本的局部审查通过，也不能自动覆盖 Writer 新增的论证。

## 6. 怎样证明优于 DS 加 DSH

主对照是同一 DS 配合指定 DSH，与同一 DS 配合本项目新控制器。双方都必须被合理配置，冻结模型版本、思考设置、工具权限、材料、时间与预算，不通过削弱 DSH 制造优势。若 DSH 不支持同一限制或工具，单列条件差异，不称严格匹配。

独立设置以下基线与消融，不必在第一轮付费时全开：

- DS 单次回答：仅作参考。
- DS 固定自查：复用已有 `self_refine`，名称保持准确。
- DS 独立多采样加答案聚合：检验收益是否只是更多采样。答案归一化不能访问金标准；平票按冻结规则处理。
- DS 加指定 DSH：主要竞争基线。
- 当前 agent：升级前基线。
- 新 agent：依次测试定点修复、调度、记忆的增量和去除单模块的效果。

无工具条件比较组织方式；同工具条件比较如何使用相同工具。主模型和审查模型均使用同一 DS；若引入更强外部模型，须另列实验并计入成本。本次软件开发使用 Luna/Terra 不属于 benchmark 求解模型。

先用旧四题及合成缺陷开发，四项联合通过本地验收后，再用八道新题作流程试验；调参后这些题归入开发集。正式比较采用新的分层留出题，暂建议四十题、每题至少三次重复；样本量最终应按试验得到的分歧率和待检测效应估计，不能预先保证统计功效。分阶段实验可以帮助归因，但不能把局部工程完成当作四项整体交付。

预登记一个主对照、一个主预算档和答案正确率主指标。额外报告完整证明盲评分、错误证明接受率、缺答率、修复成功率、全部 token/费用与延迟。按题目聚类报告不确定区间；搜索产生过正确候选但最终选错，应计选择失败，不能当最终答对。

额外诊断记录候选覆盖率与选择正确率：只有离线评估端能用答案键计算这些指标，求解控制器不得获得其反馈。这样能区分“没找到解”和“找到了却没选中”。

完整证明由不知道方案标签的独立评审按统一标准判定；内部审查通过率不能充当外部正确率。选择、修复和所有模型审查都计入求解成本，外部评分成本另列且双方一致。比较多档成本曲线，并交错题目与条件的运行顺序，减轻服务时间变化。

已知限制：公开题训练污染不能完全排除；本地评分器尚非完整官方评分器；美元硬上限、真实 DSH 适配及新增采样基线仍待实施。公平评测的源码冻结应分别记录两个 harness 和共同评分层，不能强制不同系统具有同一源码哈希。

## 7. 预期与完成定义

本升级的可检验假设是：**把计算花在不同路线、关键证据与有针对性的修复上，能比指定 DSH 更有效地把 DS 已有能力转化成正确答案和可靠证明。**

工程完成意味着上述状态、预算和恢复机制通过验收；能力提升成立还必须有冻结方案在未见留出题上的对照证据。两者分开签收。不承诺复现附件中的提升幅度，不承诺每题都受益。

四项全部实施：先落地共同的版本化状态与题内记忆，再接入缺口修复和工具证据，随后接通多路线调度与共享预算，最后联合验收。证据不足或资源较小时，调度器可以退化为单路线运行；这是已实现系统的运行选择，不是省略多路线功能。没有可靠的局部反馈时，增加搜索宽度可能只会增加错误候选和费用。形式化证明、联网文献检索、底模训练及跨题自进化保留为独立远期路线。
